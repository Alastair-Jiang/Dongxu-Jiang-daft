## 2. Milestone 1 — Institutional-grade review (morning)

A full engineering & management review was performed (institutional review framework). Headline ratings:

- **Architecture vision: Overweight** — CDAP three-way modulation is original; K3→finance mapping has real depth
- **Engineering execution: Neutral/Positive** — modular, defensive, config-driven; but zero unit tests, no CI gate
- **Validation rigor: Underweight** — in-sample backtest, no ablations, no baselines, look-ahead risks

**Core verdict:** DAFT's value hinges on one unanswered question — *does CDAP/AHM complexity buy measurable predictive gain under real data and strict out-of-sample evaluation?* Before that question is answered, every performance number is a reference value, not a conclusion.

The review produced a 30/60/90-day roadmap: validation rebuild → real data → architecture verdict → frequency test.

## 3. Milestone 2 — Baseline framework (afternoon)

**Motivation (industry rule):** complex models must beat a simple baseline to be worth discussing. A ridge regression baseline was implemented in pure PyTorch (closed-form `β = (XᵀX + λI)⁻¹Xᵀy`, no sklearn dependency), using the same 200-d feature engine as DAFT.

**Key design decisions (industry discipline):**
- Chronological split (train 80% / test 20%), evaluation on test only
- Normalization statistics fit on the training segment only, frozen for test — **no look-ahead**
- Transaction costs (5 bps + 1 bps slippage) applied in backtest

**Results:**

| Dataset | Rank IC | IC t-stat | IC>0 ratio | Net Sharpe |
|---|---|---|---|---|
| Synthetic (50×300d) | +0.009 | +0.36 | 50.0% | +1.37 (noise artifact) |
| **Real A-shares (30 stocks, 2021-2026)** | **+0.0285** | **+1.89** | 53.5% | **+0.69** |

Two important findings:
1. On synthetic HMM data the baseline finds **nothing** (IC≈0, t≈0.36) — confirming the evaluation framework does not fabricate signal, and that synthetic data is not a substitute for real markets.
2. On real A-shares the simple linear model extracts **weak but real signal** (IC 0.029, t≈1.9) — validating the feature engine itself. This is the project's first trustworthy real-world benchmark number.

## 4. Milestone 3 — Out-of-sample DAFT pipeline (afternoon/evening)

`scripts/run_full_pipeline_oos.py` runs the full DAFT training protocol with the same discipline:

- Strict chronological split: **train 60% / val 20% / test 20%** — the test segment is never exposed to training
- Normalization fit on train only
- Causal memory warm-up: the KDA memory state advances sequentially over the full panel before test-segment signal generation
- Same cost model and position sizing as the baseline

`scripts/run_oos_backtest_only.py` reuses saved checkpoints (no retraining) for fast iteration on signal generation and backtesting — this is the workflow used for the final numbers below.

**Engineering notes from this milestone:**
- Long-running training must be launched with `python -u` (unbuffered) so logs are real-time; stdout block-buffering made a healthy training run look frozen.
- A one-row signal/price alignment bug (IndexError) was found and fixed: `signals[t]` predicts `prices[t+1]` return, so the price segment must start one bar later than the signal segment.

## 5. Milestone 4 — First fair comparison (evening)

**DAFT (full, ~275K params) vs Ridge (linear, 200 params) — real A-shares, strict out-of-sample:**

| Metric | Ridge (linear) | DAFT (full) |
|---|---|---|
| Rank IC | **+0.0285** | +0.0252 |
| ICIR | +0.122 | +0.110 |
| IC t-stat | **+1.89** | +1.71 |
| IC>0 ratio | 53.5% | **55.4%** |
| Hit rate | 50.5% | 50.0% |
| **Net Sharpe** | **+0.69** | −0.70 |
| Net annual return | +11.3% | −10.0% |
| Max drawdown | −18.2% | −15.0% |
| Turnover | 0.03% | 1.7% |

**Honest reading:**

1. **Predictive power: statistically indistinguishable.** IC 0.025 vs 0.029, t-stat 1.71 vs 1.89. At the current training budget, the full architecture does not demonstrate superior prediction over a 200-parameter linear model — a concrete instance of the "linear baseline paradox" (LTSF-Linear, AAAI 2023).

2. **Trading layer: DAFT materially worse.** Net Sharpe −0.70 vs +0.69. Driver: turnover 1.7% vs 0.03% — DAFT pays transaction costs on a signal no stronger than the baseline's. Costs dominate.

3. **Not the final verdict.** Known confounds: (a) stock counts differ (20 vs 30); (b) Stage 3 early-stopped at epoch 5 with val-IC peak +0.0049 — well below the synthetic-data peak (0.108), suggesting underfitting on real data; (c) daily frequency only — the minute-level target remains untested.

**Strategic posture going forward:** keep the ridge baseline as the production-usable reference; treat DAFT's architectural claims (CDAP/AHM) as hypotheses under test, not established value.

## 7. Lessons learned (engineering)

1. Long training runs: launch with `python -u` or `stdbuf -oL`; unbuffered logs prevent false "frozen" alarms.
2. Background jobs: use `nohup ... &`, monitor the real Python child PID (not the bash wrapper), and clean stale PIDs before relaunching.
3. Signal/price alignment in backtests: `signals[t]` ↔ `prices[t+1]`; off-by-one here produces silent off-by-one evaluation or IndexError.
4. GitHub web access can be flaky; verify push state via `git log origin/main` instead.
5. `outputs/` is gitignored — experiment artifacts stay local; scripts and logs are what get committed.
